🔄 Key Data Flows

1. Code → Production Flow (Deploy)

When a developer pushes code, the CI pipeline builds a new Docker image and pushes it to the Container Registry. The pipeline then updates a version tag in the GitOps repository. Argo CD detects this Git change and automatically applies the new Kubernetes manifests to the cluster, pulling the new image and replacing the old Pods.

2. User Request → Response Flow (Traffic)

A user navigates to the application URL. The request hits the AWS Application Load Balancer, which routes traffic into the K8s cluster via the Ingress Controller. The Ingress rules direct it to the Frontend Service, which passes it to a Frontend Pod. If data is needed, the Frontend Pod calls the Backend Service, which hits a Backend Pod. Finally, the Backend Pod queries the PostgreSQL database.

3. Metrics → Dashboard Flow (Observability)

The Pods expose a /metrics endpoint. Prometheus, running inside the cluster, continuously scrapes this endpoint to pull in timeseries data (CPU usage, request rates). Grafana connects to Prometheus as a data source and renders this data into visual, real-time dashboards for engineers to monitor.
