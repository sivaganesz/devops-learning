App Build & Runtime

Understand how to compile, configure, and run modern applications natively before wrapping them in containers.

⚠️ Prerequisites
  • Phase 05: Networking Fundamentals (Ports, HTTP)
✅ What You Will Learn
  • How React+Vite and NestJS applications are built for production.
  • The difference between dev mode and production runtime.
  • How Environment Variables behave differently in Frontend vs Backend.
  • How a production system handles ports and databases.

💡 What Is It?

Every application has a lifecycle. It starts as raw source code (like TypeScript or JSX) that humans can read. Before it can be run in production, it often needs to be built (transpiled, bundled, minified) into artifacts. The runtime is the environment where these artifacts actually execute.

As a DevOps engineer, you must understand this process intimately. You cannot write a Dockerfile or a CI/CD pipeline if you don't know how the application is built natively.

🎯 Why Do We Need It?

Before

Running npm run dev starts a heavy dev server, watches files for changes, includes debugging maps, and is slow and insecure. Environment variables are hardcoded.

After

We run a build step to produce optimized artifacts in a dist/ folder. The runtime starts quickly, uses environment variables for config, and connects efficiently to databases. This is ready for Docker.

🧠 Mental Model

🧠 Mental Model

Think of building an app like publishing a book. The source code is the author's rough draft with sticky notes (dev mode). The build process is the editor and printing press creating the final bound book (artifacts). The runtime is a reader actually opening the book and reading it (production execution).

Source Code (.ts, .tsx) Build (Vite / tsc) → Artifacts (dist/) Execute (Nginx / Node) → Running Application

⚙️ How It Works

Frontend (React + Vite)

In dev mode, Vite serves unbundled code and handles Hot Module Replacement (HMR). When you run vite build, Vite bundles everything into a dist/ directory containing static HTML, CSS, and JS. In production, Vite is not running at all; you serve these static files using a web server like Nginx.

Backend (NestJS + TypeScript)

Node.js cannot run TypeScript natively. The build step (tsc) transpiles .ts files into standard JavaScript inside a dist/ folder. The production runtime command is simply node dist/main.js. You use npm ci --only=production to install only runtime dependencies, skipping heavy dev packages.

Environment Variables

Follow the 12-factor app methodology: config belongs in the environment. In backend apps, process.env.DATABASE_URL is read dynamically at runtime. However, in frontend apps (Vite), variables prefixed with VITE_ are baked into the static JS files during the build process. The browser has no concept of OS environment variables.

🔗 How This Applies to TaskFlow

TaskFlow Project

Our Running Example

To run the TaskFlow stack fully:

  • Database: Needs to be running on port 5432. We run migrations to build tables.
  • Backend: We run npm run build, provide DATABASE_URL via environment, and run node dist/main.js on port 3000. It needs a /health endpoint for production monitoring.
  • Frontend: We build with VITE_API_URL=http://localhost:3000. Then we serve the dist/ folder using Nginx on port 80.
  • CORS: Because dev frontend (5173) and backend (3000) are different origins, the backend must be configured to allow CORS during development.

⚠️ Common Mistakes

❌ Mistake: Using a Dev Server in Production
✅ Fix: Never run npm run dev or vite in production. It is not optimized, lacks security features, and is highly inefficient. Always build to static artifacts and serve with Nginx (Frontend) or run the transpiled JS with node (Backend).

🔧 Troubleshooting

  • Symptom: Frontend in production tries to call API at "localhost" Cause: VITE_API_URL was set to localhost during the build step. Remember frontend vars are baked in at build time! Fix: Rebuild the frontend providing the correct production API URL.
  • Symptom: Backend fails to start with "Cannot find module 'dist/main.js'" Cause: You tried to run the app without running the build step first. Fix: Run npm run build (which executes tsc) before trying to start.

🏋️ Practice Exercise

Hands-On Exercise

Inspect Build Artifacts

  1. Create a dummy Vite app: npm create vite@latest test-app -- --template react-ts.
  2. Run npm install then npm run build.
  3. Inspect the newly created dist/ folder. Open the JS file and notice it is minified and unreadable.
  4. Try to run it with a static file server: npx serve -s dist and open it in a browser.

🧪 Knowledge Check

npm ci strictly follows package-lock.json and will fail if it's out of sync. It is faster because it bypasses package resolution and guarantees exact identical dependency versions.

Frontend code runs in the user's browser, which has no access to your server's environment variables. Therefore, build tools (like Vite) must inject the variable values directly into the static JS files during the build process.
