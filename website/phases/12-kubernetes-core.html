💡 What Is It?

Kubernetes (K8s) is an open-source container orchestration system originally designed by Google. Think of it as an operating system for a cluster of machines. It handles deciding where containers should run, restarting them if they crash, scaling them out, and managing their networking seamlessly.

🎯 Why Do We Need It?

Before

Docker Compose is great, but it doesn't solve running containers across multiple servers. If a server dies, containers don't auto-restart elsewhere. Rolling updates and self-healing had to be scripted manually.

After

Kubernetes orchestrates containers across hundreds of hosts. It ensures the "desired state" matches reality. If a node fails, K8s reschedules the workloads automatically.

🧠 Mental Model

🧠 Mental Model

Imagine a restaurant manager (Kubernetes). You give them a menu (YAML manifest) saying "We need 3 chefs working." If a chef gets sick (container crashes), the manager automatically hires a new one to keep the kitchen running exactly as requested.

Cluster → Node → Deployment → ReplicaSet → Pod

⚙️ How It Works

The core of Kubernetes is its declarative reconciliation loop. You tell Kubernetes what you want (the desired state stored in etcd), and controllers continuously work to ensure the cluster matches that state.

The architecture consists of:

  • Control Plane (Master): The brain.
    • kube-apiserver: The frontend, handling all REST API calls.
    • etcd: Distributed key-value store containing cluster state.
    • kube-scheduler: Assigns new Pods to Nodes.
    • kube-controller-manager: Runs the controllers managing nodes, deployments, etc.
  • Worker Nodes: Where containers run.
    • kubelet: The agent on each node ensuring containers are running.
    • kube-proxy: Manages network rules (iptables) for Service routing.
    • Container Runtime: e.g. containerd (Docker is no longer used directly).

📚 Core Concepts

📦
Pod
The smallest atomic unit. Contains one or more containers sharing a network namespace and volumes. Pods are ephemeral.
🔄
Deployment
A higher-level abstraction that manages ReplicaSets, enabling declarative updates, scaling, and rollbacks.
🏷️
Labels & Selectors
Key-value tags applied to objects. Used extensively by Services and Deployments to link components dynamically.

🔗 How This Applies to TaskFlow

TaskFlow Project

Our Running Example

For TaskFlow, we use a Deployment to run 3 replicas of the NestJS backend and another Deployment for the React Vite frontend. This ensures high availability. We use labels like app: taskflow-backend so that our network routing can find these pods, even as Kubernetes dynamically creates and destroys them during scaling or updates.

💻 Commands & Configuration

yaml 
apiVersion: apps/v1
kind: Deployment
metadata:
  name: taskflow-backend
  labels:
    app: taskflow-backend
spec:
  replicas: 3
  selector:
    matchLabels:
      app: taskflow-backend
  template:
    metadata:
      labels:
        app: taskflow-backend
    spec:
      containers:
      - name: backend
        image: gitlab.com/yourname/taskflow/backend:v1
        ports:
        - containerPort: 3000
        env:
        - name: DATABASE_URL
          value: "postgres://user:pass@db:5432/taskflow"
↑ Deployment YAML for the TaskFlow backend ensuring 3 instances are always running.
bash 
# Apply the configuration
kubectl apply -f deployment.yaml

# Check the status of pods
kubectl get pods -l app=taskflow-backend

# View logs for a specific pod
kubectl logs deploy/taskflow-backend

# Access the pod locally for testing
kubectl port-forward deploy/taskflow-backend 3000:3000

⚠️ Common Mistakes

❌ Deploying naked Pods
✅ Fix: Never deploy raw Pods in production. They are ephemeral and will not restart if the Node fails. Always wrap them in a Deployment.

🔧 Troubleshooting

  • Symptom: Pod status is CrashLoopBackOff Cause: The container application is crashing upon startup. Fix: Check logs with kubectl logs <pod-name> to find the application error.
  • Symptom: Pod status is ImagePullBackOff Cause: Kubelet cannot fetch the container image. Fix: Verify the image name, tag, and registry credentials (imagePullSecrets).

🏋️ Practice Exercise

Hands-On Exercise

Create and scale a Deployment

  1. Install `minikube` or use Docker Desktop Kubernetes.
  2. Write a `nginx-deploy.yaml` file declaring 2 replicas of the `nginx:alpine` image.
  3. Run `kubectl apply -f nginx-deploy.yaml`.
  4. Observe the pods: `kubectl get pods -w`.
  5. Delete one of the pods manually: `kubectl delete pod <pod-name>`. Watch how Kubernetes instantly creates a new one.
  6. Scale it up: `kubectl scale deployment nginx-deployment --replicas=5`.

🧪 Knowledge Check

Kubernetes removed Dockershim because Docker is a heavy, multi-tool daemon not fully compliant with the Container Runtime Interface (CRI). Kubernetes now communicates directly with CRI-compatible runtimes like containerd or CRI-O.
