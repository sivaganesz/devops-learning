DevOps Fundamentals

Understand the culture, practices, and mindset that bridge the gap between software development and IT operations.

⚠️ Prerequisites
  • Basic understanding of what software development is
  • No prior operational or sysadmin experience required
✅ What You Will Learn
  • What DevOps actually means beyond the buzzword
  • The software development life cycle (SDLC)
  • The cultural pillars of DevOps
  • High-level overview of Continuous Integration and Deployment (CI/CD)

💡 What Is It?

DevOps is a combination of Development (Dev) and Operations (Ops). It is not a single tool, a specific role, or a piece of software you can buy. Rather, it is a culture, practice, and mindset aimed at shortening the systems development life cycle and providing continuous delivery with high software quality.

Traditionally, developers wrote code (Dev) and literally "threw it over the wall" to system administrators (Ops) to deploy and maintain. This created conflicting goals: Devs wanted to ship new features quickly, while Ops wanted absolute stability (which usually means changing nothing). DevOps bridges this gap through shared ownership, automation, and continuous feedback.

🎯 Why Do We Need It?

Before

The Wall of Confusion: Developers and Operations worked in silos. Releases took months, leading to massive, risky deployments. When things broke, a "blame culture" emerged. Developers claimed "it works on my machine," while Ops struggled with undocumented deployment steps.

After

Shared Responsibility: Teams adopt the mantra "you build it, you run it." Deployments happen multiple times a day using automated pipelines. Failures are treated as learning opportunities via blameless post-mortems. The focus is on fast feedback and continuous improvement.

🧠 Mental Model

🧠 Mental Model

Think of DevOps like a high-performance Formula 1 pit crew. The driver (Dev) and the mechanics (Ops) aren't separate entities working against each other; they are a single team optimizing the car's performance and minimizing pit stop time.

Developer → Git (Version Control) → CI/CD Pipeline (Automation) → Deploy → Monitor → User Feedback

⚙️ How It Works

DevOps transforms the traditional Software Development Life Cycle (SDLC) by automating and integrating the following phases:

  • Plan: Define business value and requirements.
  • Code: Write software and manage versions (Git).
  • Build: Compile code and package it into deployable artifacts (e.g., Docker images).
  • Test: Run automated unit, integration, and security tests.
  • Release: Approve the artifact for deployment.
  • Deploy: Automatically push the artifact to production servers or Kubernetes clusters.
  • Operate: Manage the infrastructure and scaling.
  • Monitor: Collect logs and metrics to ensure health and gather user feedback.

Crucially, this is driven by CI/CD:

  • Continuous Integration (CI): Merging all developer working copies to a shared mainline several times a day, automatically running tests on every commit.
  • Continuous Delivery (CD): Ensuring the software is always in a deployable state. Deployments might still require a manual click.
  • Continuous Deployment (CD): Every change that passes automated tests is deployed to production automatically.

TaskFlow Project

Our Running Example

Throughout this course, we will build and deploy TaskFlow, a full-stack application:

  • Frontend: React + Vite (Dev port 5173, builds to /dist)
  • Backend: NestJS on Node.js (Port 3000)
  • Database: PostgreSQL (Port 5432)

This entire automated flow is the embodiment of DevOps!

⚠️ Common Mistakes

❌ Thinking DevOps = Just CI/CD Tools
✅ Fix: Understand that tools like Docker and Kubernetes are useless without a culture of communication, shared ownership, and fast feedback.
❌ Hiring a "DevOps Engineer" to solve organizational silos
✅ Fix: DevOps is a practice everyone in the engineering organization must adopt, from developers to security to QA.

🔧 Troubleshooting

  • Symptom: Developers are afraid to deploy to production on Fridays. Cause: Deployments are manual, error-prone, and lack automated testing safety nets. Fix: Implement Continuous Delivery with high test coverage and automated rollbacks.

🧪 Knowledge Check

Continuous Delivery means the code is *ready* to be deployed at any time, but requires a manual approval/click. Continuous Deployment means the code goes to production entirely automatically if tests pass.

It shifts the focus from punishing individuals (which causes people to hide mistakes) to fixing the systemic issues and processes that allowed the mistake to happen.
