TaskFlow: End-to-End Project

The capstone project. Bringing together every concept from all 20 phases to build a fully production-ready, monitored, GitOps-deployed application.

⚠️ Prerequisites
  • Completion of Phases 1-20
  • An AWS account and GitLab account
  • Local tooling installed (Docker, kubectl, terraform, helm)
✅ What You Will Learn
  • How a complete modern DevOps pipeline fits together
  • Writing IaC, Kubernetes manifests, and CI/CD from scratch
  • GitOps workflows with Argo CD
  • Implementing full observability and security

💡 Introduction: The Culmination

This is where everything comes together. You have learned Linux, Networking, Docker, Terraform, CI/CD, Kubernetes, Monitoring, and Security in isolation. This page is the culmination of the entire curriculum.

We are going to take TaskFlow—our sample task management application featuring a React+Vite frontend, a NestJS backend, and a PostgreSQL database—from zero to a highly available, monitored, GitOps-deployed application running on an AWS EKS cluster.

🎯 Project Goals

The Source Code

Raw application code sitting on a developer's laptop. Prone to "it works on my machine" syndrome, manual deployment errors, lack of monitoring, and insecure configurations.

The Production System

Infrastructure provisioned via code. Code automatically tested, scanned, and built into immutable container images. Argo CD continuously syncing desired state to the cluster. Dashboards monitoring health.

🧠 The Big Picture

🧠 The Complete Journey

Think of this as a highly automated factory. The Developer pushes raw materials (code). The CI pipeline is the assembly line that tests, secures, and packages the product (Docker images). The Container Registry is the warehouse. GitOps (Argo CD) is the logistics manager that pulls the product and delivers it to the storefront (Kubernetes), while Monitoring acts as the security cameras and quality assurance team.

Code Push → GitLab CI (Build/Test) → GitOps Repo Update → Argo CD Sync → EKS Production

🏗️ Complete Architecture

Infrastructure: AWS VPC with public and private subnets, EKS Cluster in private subnets, ALB for ingress, RDS PostgreSQL for the database.

Kubernetes Workloads: Frontend Pods (Nginx), Backend Pods (NestJS), Ingress Controller, External Secrets Operator, Prometheus & Grafana.

🚀 Stages 1-3: Local, Docker, and Git

Stage 1: Local Development
We start by running the app locally. Frontend runs via npm run dev on port 5173. Backend runs via npm run start:dev on port 3000. We spin up a local PostgreSQL instance using:
docker run -d -p 5432:5432 -e POSTGRES_PASSWORD=dev postgres:15

Stage 2: Dockerize
We create multi-stage Dockerfiles. The frontend uses Node to build the static React assets, then copies them to an Nginx image. The backend compiles TypeScript and runs in a distroless Node environment. A docker-compose.yml file orchestrates the local stack.

Stage 3: Repository Setup
We create two repositories on GitLab: taskflow (the application code) and taskflow-gitops (our Kubernetes manifests/Helm charts). We protect the main branches and require Merge Requests.

💻 Stage 4: CI/CD Pipeline

yaml 
# .gitlab-ci.yml
stages:
  - test
  - build
  - push
  - update-gitops

variables:
  IMAGE_TAG: $CI_COMMIT_SHORT_SHA

test_backend:
  stage: test
  image: node:18
  script:
    - cd backend && npm install && npm test

build_and_push:
  stage: build
  image: docker:20.10.16
  services:
    - docker:20.10.16-dind
  script:
    - docker build -t $CI_REGISTRY_IMAGE/backend:$IMAGE_TAG ./backend
    - docker login -u $CI_REGISTRY_USER -p $CI_REGISTRY_PASSWORD $CI_REGISTRY
    - docker push $CI_REGISTRY_IMAGE/backend:$IMAGE_TAG
    # run trivy scan here

update_gitops:
  stage: update-gitops
  image: alpine/git
  script:
    - git clone https://oauth2:${GITOPS_TOKEN}@gitlab.com/yourname/taskflow-gitops.git
    - cd taskflow-gitops
    # Update image tag in values.yaml
    - sed -i "s/tag: .*/tag: ${IMAGE_TAG}/g" charts/taskflow/values.yaml
    - git add . && git commit -m "Update image tag to ${IMAGE_TAG}"
    - git push origin main
↑ The pipeline tests the code, builds the container, pushes to the registry, and crucially, automatically updates the GitOps repository with the new image tag.

☁️ Stages 5-7: AWS, Kubernetes, and Helm

Stage 5: AWS Infrastructure (Terraform)
We write main.tf declaring our VPC, subnets, EKS cluster, and an RDS instance for our production database. After running terraform apply, we connect our local kubectl to the new EKS cluster.

Stage 6: Kubernetes Manifests
We write Deployments, Services, ConfigMaps, and an HPA. We use an Ingress resource to route /api traffic to the NestJS backend and all other traffic to the React frontend.

Stage 7: Helm Chart
We convert our raw YAML manifests into a reusable Helm chart located in our taskflow-gitops repo. We create a production-values.yaml file for environment-specific overrides (like resource limits and replica counts).

🐙 Stage 8: GitOps with Argo CD

We install Argo CD into the cluster:
helm install argo-cd argo/argo-cd -n argocd --create-namespace

We create an Argo CD Application resource that points to our taskflow-gitops repository. From this point forward, NO ONE runs kubectl apply manually. When our CI pipeline pushes a new commit to the GitOps repo (updating the image tag), Argo CD detects the change and automatically syncs the cluster state.

🛡️ Stages 9-10: Monitoring & Security

Stage 9: Monitoring
We deploy the kube-prometheus-stack. We configure a ServiceMonitor to scrape metrics from the NestJS backend's /metrics endpoint. We build a Grafana dashboard visualizing API request rates and database connection pool health. We set up an alert to notify Slack if P99 latency exceeds 2 seconds.

Stage 10: Security Hardening
We apply Pod Security Standards (Restricted). We set up External Secrets Operator to sync the RDS database password from AWS Secrets Manager directly into Kubernetes. We install cert-manager for automatic Let's Encrypt TLS certificates.

⚠️ Common Mistakes in the Pipeline

❌ Mistake: Modifying resources via kubectl while using Argo CD.
✅ Fix: Argo CD will detect the manual change as "OutOfSync" and (if auto-heal is on) immediately overwrite your manual change with what is in Git. All changes MUST go through Git.

🔧 Troubleshooting the Pipeline

  • Symptom: Pipeline fails at "update-gitops" stage. Cause: The pipeline does not have permission to push to the taskflow-gitops repository. Fix: Ensure you generated a Project Access Token in the GitOps repo and added it as a masked CI/CD variable (`GITOPS_TOKEN`) in the application repo.

🏁 The Final Diagram

When a developer pushes code to main at T+0:

  • T+0:05: GitLab CI starts running tests.
  • T+2:00: Docker image built, Trivy scan passes, image pushed to registry.
  • T+2:05: CI updates values.yaml in the GitOps repo.
  • T+2:10: Argo CD detects the Git commit.
  • T+2:30: Kubernetes begins a RollingUpdate with zero downtime.
  • T+3:00: Old pods terminate, new pods are fully serving traffic. Prometheus confirms error rate is 0%.
