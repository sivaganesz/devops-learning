💡 What Is It?

Cloud computing is the practice of renting compute, storage, and networking resources from a provider instead of buying and managing physical hardware yourself. Services are on-demand, pay-per-use, and globally distributed.

Cloud services are generally categorized into three models:

  • IaaS (Infrastructure as a Service): You manage everything from the OS layer upwards. Example: AWS EC2.
  • PaaS (Platform as a Service): You manage only the application code and data. Example: AWS RDS, Heroku.
  • SaaS (Software as a Service): You just use the software. Example: Gmail, Salesforce.

🎯 Why Do We Need It?

Before

Deploying a new server took weeks of purchasing hardware, racking it in a datacenter, setting up networking, and installing an OS. Scaling up for traffic spikes was nearly impossible.

After

You can provision thousands of servers globally in minutes using APIs. You only pay for what you use, and can auto-scale resources dynamically based on demand.

🧠 Mental Model

🧠 Mental Model

Think of AWS as a massive, globally distributed data center that you interact with entirely via remote controls (APIs/CLI). A VPC is your own fenced-off plot of land in that data center.

Region → VPC → Subnet → EC2 / ALB / RDS

⚙️ How It Works

AWS operates a global infrastructure of Regions (physical locations like us-east-1). Each region contains multiple Availability Zones (AZs), which are isolated data centers. Deploying across multiple AZs ensures high availability.

At the core of AWS networking is the VPC (Virtual Private Cloud). A VPC uses a CIDR block (e.g., 10.0.0.0/16) and is divided into subnets.

  • Public Subnets: Have a route to an Internet Gateway. They host load balancers and bastion hosts.
  • Private Subnets: Do not have direct internet access. They host application servers (like EKS worker nodes) and databases (RDS). A NAT Gateway allows them to pull updates from the internet securely.

📚 Core Concepts

🖥️
EC2 (Elastic Compute Cloud)
Virtual machines. Can be categorized by instance types (e.g., t3.micro for burstable CPU, c5.xlarge for compute optimized). Use AMIs (Amazon Machine Images) to template OS configurations.
🗄️
Storage (EBS, S3, EFS)
EBS is block storage attached to EC2. S3 is object storage for files. EFS is a shared file system.
🔐
IAM (Identity and Access Management)
Users, Groups, Roles, and Policies to control who can do what. Use Roles for EC2/EKS nodes instead of hardcoded credentials.

🔗 How This Applies to TaskFlow

TaskFlow Project

Our Running Example

TaskFlow runs in an AWS VPC (10.0.0.0/16) across 3 AZs. The ALB sits in the public subnets (10.0.1.0/24, 10.0.2.0/24, 10.0.3.0/24) receiving traffic. It forwards to the NestJS backend and React frontend hosted in an EKS cluster running in private subnets. The PostgreSQL database is an RDS instance, also in the private subnets. An S3 bucket serves as a backup or static hosting alternative for the React frontend.

💻 Commands & Configuration

bash 
# Configure AWS CLI credentials
aws configure

# List all S3 buckets
aws s3 ls

# Describe running EC2 instances and filter for the TaskFlow application
aws ec2 describe-instances --filters "Name=tag:App,Values=TaskFlow"

# Create an S3 bucket for the TaskFlow frontend
aws s3 mb s3://taskflow-frontend-static
↑ The AWS CLI allows you to interact with AWS APIs directly from your terminal. Never commit the access keys from `aws configure` to version control.

⚠️ Common Mistakes

❌ Hardcoding AWS Access Keys in code or GitHub
✅ Fix: Use IAM Roles attached to EC2 instances or EKS pods. If running locally, rely on `~/.aws/credentials` or environment variables, never source code.
❌ Putting databases in public subnets
✅ Fix: Always place RDS and core worker nodes in private subnets. Use public subnets only for resources that MUST be internet-facing (like ALBs and NAT Gateways).

🔧 Troubleshooting

  • Symptom: Cannot SSH into an EC2 instance Cause: Security group is missing inbound rule on port 22, or the wrong key pair is used. Fix: Ensure Security Group allows port 22 from your IP and use the correct `.pem` key.
  • Symptom: Pods in private subnet cannot pull Docker images Cause: The private subnet lacks a NAT Gateway in the route table. Fix: Create a NAT Gateway in a public subnet and add a route `0.0.0.0/0` targeting it in the private subnet's route table.

🏋️ Practice Exercise

Hands-On Exercise

AWS CLI Explorer

  1. Install the `aws-cli` on your local machine.
  2. Run `aws configure` to set up an IAM user with programmatic access.
  3. Run `aws ec2 describe-vpcs` to see the default VPC in your region.
  4. Create a new S3 bucket: `aws s3 mb s3://my-test-bucket-[YOUR-NAME]`.
  5. Upload a file: `echo "Hello" > test.txt && aws s3 cp test.txt s3://my-test-bucket-[YOUR-NAME]/`.
  6. Clean up: `aws s3 rm s3://my-test-bucket-[YOUR-NAME]/test.txt` and `aws s3 rb s3://my-test-bucket-[YOUR-NAME]`.

🧪 Knowledge Check

IAM Roles provide temporary credentials that rotate automatically. Using an IAM User would require placing permanent credentials (access keys) on the server, which is a major security risk if the server is compromised.
