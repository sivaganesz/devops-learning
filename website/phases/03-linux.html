💡 What Is It?

Linux is an open-source operating system kernel that serves as the foundation for nearly all modern infrastructure. Over 90% of cloud servers, all Docker containers, and Kubernetes nodes run on Linux. Unlike Windows, which relies heavily on GUIs, Linux is primarily managed via the CLI (Command Line Interface), making it perfect for automation and scripting in DevOps.

🎯 Why Do We Need It?

Before

Deploying software involved manually clicking through Wizards on a Windows Server GUI, which cannot be easily tracked in version control, automated in CI/CD, or replicated quickly across 100 servers.

After

Using Linux, infrastructure is managed purely through text files, commands, and scripts. This enables Infrastructure as Code, automated deployments, and seamless containerization.

🧠 Mental Model

🧠 Mental Model

Think of a Linux server like a massive filing cabinet and engine room combined. The filesystem tree is the filing cabinet where absolutely everything (even hardware) is treated as a file. The processes and daemons are the workers keeping the engine running.

Hardware → Linux Kernel → System Daemons (systemd) → User Applications (TaskFlow)

⚙️ How It Works

The Filesystem Hierarchy

  • / : Root directory, the top of the hierarchy.
  • /bin & /sbin : Essential command binaries.
  • /etc : Configuration files (like `.env` for the whole OS).
  • /var : Variable data like databases and /var/log/ for logs.
  • /home : User directories (e.g., /home/sivamuthu).
  • /tmp : Temporary files wiped on reboot.

Permissions & Ownership

Every file has an owner, a group, and permissions for Owner (u), Group (g), and Others (o). Permissions are Read (r=4), Write (w=2), and Execute (x=1).

chmod 755 file = Owner gets 7 (4+2+1=rwx), Group gets 5 (4+1=r-x), Others get 5 (r-x). 600 means only the owner can read/write (used for SSH private keys).

Process Signals

When you kill a process, you send a signal. SIGTERM (15) politely asks the process to save data and shut down cleanly. SIGKILL (9) forces the kernel to terminate it immediately. Always try 15 first to allow graceful shutdowns in containers!

SSH (Secure Shell)

Used to remotely log into servers securely. It uses asymmetric cryptography. You generate a keypair (ssh-keygen), keep the private key safe, and put the public key on the server (~/.ssh/authorized_keys). Passwords are too easily brute-forced and should be disabled.

🔗 How This Applies to TaskFlow

TaskFlow Project

Manual Deployment on Linux Server

Before we learn Docker, let's understand how you'd manually host the TaskFlow API on an Ubuntu VM:

  1. SSH into server: ssh ubuntu@myserver.com
  2. Install deps: sudo apt update && sudo apt install nodejs npm
  3. Clone repo: git clone gitlab.com/yourname/taskflow
  4. Build it: npm ci && npm run build
  5. Create systemd file: /etc/systemd/system/taskflow.service
  6. Start it: sudo systemctl enable --now taskflow
  7. Check logs: journalctl -u taskflow -f

⚠️ Common Mistakes

❌ Using `chmod 777` to fix permission issues
✅ Fix: 777 gives everyone read/write/execute access, posing a massive security risk. Figure out which user/group actually needs access and use `chown` and specific `chmod` (like 644 or 755).
❌ Forgetting to run `apt update` before `apt install`
✅ Fix: The local package index gets stale. Always update it first to avoid 404 Not Found errors when downloading packages.

🔧 Troubleshooting

  • Symptom: SSH Connection Refused / Permission Denied Cause: SSH key has wrong permissions, or wrong user specified. Fix: chmod 600 ~/.ssh/id_rsa (Private key MUST not be readable by others).
  • Symptom: No space left on device Cause: Disk is full (often due to huge logs). Fix: Run df -h to see disks, du -sh * to find large folders, and clear `/var/log`.

🏋️ Practice Exercise

Hands-On Exercise

Navigate and Manipulate the Filesystem

  1. Create a directory structure: mkdir -p /tmp/devops/logs
  2. Create an empty file: touch /tmp/devops/logs/app.log
  3. Add content using redirection: echo "Application started" > /tmp/devops/logs/app.log
  4. Append content: echo "ERROR: DB Connection failed" >> /tmp/devops/logs/app.log
  5. Grep for errors: grep "ERROR" /tmp/devops/logs/app.log
  6. Change permissions so only you can read it: chmod 600 /tmp/devops/logs/app.log

🧪 Knowledge Check

> overwrites the destination file completely with the new output. >> appends the output to the end of the destination file.

SIGTERM politely asks the process to stop, allowing it to close database connections and finish requests. SIGKILL forces the kernel to instantly terminate the process, potentially corrupting data.
